## 1. 引言

### 1.1 编写目的

本文档定义「业余无线电 QSO 记录聚合与 QSL 卡片打印系统」（以下简称「本系统」）的完整软件需求，作为设计、开发、测试、验收和印刷交付的共同依据。文档描述系统从 ADIF 日志文件、QRZ.com、ARRL Logbook of The World（LoTW）、eQSL.cc、Club Log、HamQTH 等渠道获取并聚合业余无线电 QSO（通联）记录，补全对方呼号的台站信息与邮寄地址，并按照用户定义的模板批量生成可直接交付打印/印刷的 QSL 卡片文件（含正反面拼版、裁切线、出血与投递标签）。

### 1.2 项目范围

本系统覆盖以下端到端链路：

1. **获取**：从多种数据源导入/拉取 QSO 记录与确认（QSL）状态；
2. **标准化**：统一为内部规范数据模型，完成去重、合并、清洗与实体派生；
3. **补全**：通过 Callbook 服务补全对方姓名、QTH、地址、网格、DXCC 实体等；
4. **筛选**：按规则（如「已确认 LoTW 则不发卡」「仅发 DXCC 新实体」）选出需要制卡的 QSO；
5. **制卡**：套用模板渲染卡片正反面，生成拼版 PDF 等印刷文件；
6. **投递**：生成投递标签/信封数据（Direct / Bureau / OQRS）；
7. **追踪**：记录卡片发出与回收状态，形成闭环。

## 2. 项目概述

### 2.1 背景与痛点

业余无线电爱好者在完成通联后，通常需要寄送或回复 QSL 卡片以确认通联、申请奖项（DXCC、WAS、IOTA、POTA 等）。当前通行做法存在以下痛点：

1. **数据源分散**：QSO 记录存在于 ADIF 文件、QRZ Logbook、LoTW、eQSL、Club Log 等多处，状态（是否已确认）不统一；
2. **手工制卡繁琐**：逐个 QSO 打开制图软件复制粘贴呼号、时间、频率，效率极低，易错；
3. **地址补全困难**：Direct 寄卡需要对方邮寄地址，逐台查询 Callbook 耗时；
4. **印刷不专业**：自行拼版难以处理出血、裁切线、双面套准，裁切后卡片歪斜或正反面错位；
5. **状态难追踪**：发出后是否收回、是否需要补寄，缺少台账。

### 2.2 产品目标

| 编号 | 目标 |
| --- | --- |
| G-01 | 一站式聚合多源 QSO 记录与确认状态，形成单一可信台账 |
| G-02 | 将「选卡 → 制卡 → 拼版 → 出片」压缩为可批处理的一键流程 |
| G-03 | 生成满足商业印刷要求（出血、裁切线、双面套准、300+ DPI）的印刷文件 |
| G-04 | 自动补全对方台站信息与邮寄地址，支持 Direct / Bureau / OQRS 路由 |
| G-05 | 卡片发出与回收状态可追踪、可导出、可与日志软件交换 ADIF |

### 2.3 成功度量（KPI）

| 指标 | 目标值 | 测量方式 |
| --- | --- | --- |
| ADIF 导入 10 万条记录耗时 | ≤ 60 秒 | 基准测试（中端笔记本） |
| 1000 张卡片 PDF 生成耗时 | ≤ 120 秒 | 基准测试 |
| 双面套准误差 | ≤ 0.5 mm | 打样实测（100 张抽样） |
| 数据源字段映射准确率 | ≥ 99%（抽样 500 条人工核对） | 测试报告 |
| 去重误合并率 | ≤ 0.1% | 测试用例集 |
| 制卡人工操作步数 | ≤ 3 步（选记录 → 选模板 → 生成） | 可用性测试 |

### 2.4 用户角色

| 角色 | 描述 | 核心诉求 |
| --- | --- | --- |
| 个人火腿 | 偶尔通联、按需制卡 | 简单、少配置、一次几十张 |
| 竞赛/远征台 | 通联量大、集中回卡 | 批量、模板一致、Bureau 大批量 |
| DX 猎手 | 追求新实体/新波段确认 | 只发未确认的、按奖项筛选 |
| QSL 管理员（Manager） | 代多个呼号收发卡 | 多呼号、多地址、台账清晰 |
| 俱乐部/卡片打印服务商 | 为他人印制卡片 | 印刷规格严格、批量、成本可控 |
| 领域专家 | 校验字段与业务规则 | 规则可解释、可审计 |

### 2.5 典型使用场景（用户故事）

| 编号 | 用户故事 |
| --- | --- |
| US-01 | 作为个人火腿，我希望导入 WSJT-X/Log4OM 导出的 ADIF，只给「尚未被 LoTW 确认」的 QSO 制卡，以便省下不必要的卡片与邮费。 |
| US-02 | 作为 DX 猎手，我希望按「新 DXCC 实体」或「新波段」筛选，以便优先申请奖项。 |
| US-03 | 作为竞赛台，我希望把 2000 条 QSO 一次性拼版到 A4 纸（每页 4 张）并输出双面 PDF，以便送印刷厂。 |
| US-04 | 作为寄卡用户，我希望自动从 QRZ 拉取对方姓名与地址并打印 Direct 邮件标签，以便免去手抄。 |
| US-05 | 作为 QSL 管理员，我希望从 Club Log OQRS 导入索卡请求与其地址，以便只回复真正要卡的人。 |
| US-06 | 作为用户，我希望卡片发出后更新状态并导出 ADIF，以便把状态回合日志软件。 |
| US-07 | 作为设计者，我希望能自定义卡片正反面模板并实时预览，以便保持个人风格。 |
| US-08 | 作为用户，我希望断网也能使用（用本地缓存与离线实体表），以便在无网络环境制卡。 |

### 2.6 假设

- A-01 用户拥有合法呼号，并有权限使用其 QRZ/LoTW/eQSL/Club Log 账号；
- A-02 用户本地可安装 TQSL（用于 LoTW 交互）并已导入个人证书；经用户显式授权，程序可调用 TQSL 命令行并使用证书口令完成签名/上传/下载；
- A-03 印刷目标以**家用打印机（喷墨/激光，A4/Letter）为主要场景**，商业印刷为可选增强；最终交付格式统一为 PDF；
- A-04 系统运行于 Windows 10/11 优先，macOS/Linux 为次要平台；
- A-05 用户对 QSL 卡片尺寸、纸张与印刷工艺有最终决定权。

### 2.7 约束

- C-01 必须遵守各第三方服务的服务条款与速率限制，不得抓取未授权数据；
- C-02 API 密钥、LoTW 证书口令等敏感信息不得明文存储或上传；
- C-03 对方地址属个人信息，须遵循最小化与本地化存储原则（参考 GDPR 类要求）；
- C-04 LoTW 无公开的通用 REST API，交互必须通过 TQSL 命令行或官方网页导出；**允许程序调用 TQSL CLI 并使用用户提供的证书口令**，但口令不得落盘、不得写日志（详见 SR-LOTW-009/010）；
- C-05 QRZ XML 查询为付费订阅服务，无订阅时须降级到其他 Callbook 或手工录入；
- C-06 **用户提供的凭证（账号、密码、API Key、证书口令）仅限本地保存、仅限本地调用**，不得上传、不得云同步、不得写入任何导出物（详见第 18 章）；
- C-07 本系统为纯本地应用，不设开发者运营的服务器，不采集遥测或使用统计。

### 2.8 不在范围内（Out of Scope）

- 不替代标准日志软件（N1MM+、Log4OM、DXKeeper 等）的日志编辑与竞赛功能；
- 不代办 LoTW 证书申请、不代为签名上传（仅调用用户本地 TQSL）；
- 不提供在线支付、不代寄实体邮件、不承接印刷生产；
- 不实现 DXCC/IOTA 等官方奖项的在线申报提交；
- 不提供公共多租户 SaaS（首版为本地单用户；多用户为可选演进项）；
- 不提供云同步、在线账号体系、远程日志或使用统计上报（隐私要求见第 18 章）。

## 3. 系统总体设计

### 3.1 逻辑分层

| 层 | 职责 | 主要组件 |
| --- | --- | --- |
| 表现层 | 交互、向导、预览 | 桌面 GUI（首版）/ CLI / 可选 Web UI |
| 连接器层（Connector） | 各数据源的认证、请求、解析、限流、重试 | ADIF、QRZ XML、QRZ Logbook、LoTW/TQSL、eQSL、Club Log、HamQTH、本地日志源 |
| 规范化层 | 字段映射、单位/编码统一、校验、去重合并 | Normalizer、Deduplicator、Validator |
| 存储层 | QSO 台账、台站档案、模板、任务、凭据 | 本地数据库（SQLite 首版，可换 PostgreSQL） |
| 业务服务层 | 筛选规则、制卡任务、状态机、报表 | SelectionEngine、CardService、TrackingService |
| 渲染输出层 | 模板渲染、拼版、PDF 生成、标签 | TemplateEngine、ImpositionEngine、PdfWriter |

### 3.2 数据流

~~~mermaid
flowchart LR
  A[ADIF 文件] --> N[规范化/去重]
  B[QRZ Logbook] --> N
  C[LoTW via TQSL] --> N
  D[eQSL] --> N
  E[Club Log / OQRS] --> N
  N --> DB[(QSO 台账)]
  F[QRZ/HamQTH Callbook] --> CB[台站与地址补全]
  DB --> CB
  CB --> SEL[筛选规则引擎]
  SEL --> TPL[模板渲染]
  TPL --> IMP[拼版/出血/裁切线]
  IMP --> PDF[印刷用 PDF]

  LBL --> TRK
  TRK --> DB
~~~

### 3.3 部署形态

| 形态 | 说明 | 优先级 |
| --- | --- | --- |
| 本地桌面应用（GUI） | **首版主要形态**：单人使用，数据完全本地，离线可用 | 必须（主要） |
| 命令行（CLI） | 与 GUI 共用同一核心，便于批处理、脚本化、CI 化验证 | 必须（补充） |
| 本地 Web（localhost） | 可选，便于远程桌面/多设备预览 | 可选 |

### 3.4 技术选型建议（非强制）

- 语言/运行时：Python 3.11+（生态成熟：ADIF 解析、PDF、图像、GUI）；
- 数据存储：SQLite（单用户）/ PostgreSQL（多用户）；
- 模板：Jinja2 + HTML/CSS 渲染为 PDF，或 SVG 模板；图像处理 Pillow；
- PDF 生成：ReportLab / WeasyPrint / PyMuPDF（择一，需支持嵌入字体与 300+ DPI）；
- GUI：PySide6/Qt 或 Tauri + 前端；
- 打包：PyInstaller（Windows）/ 原生安装包；
- 测试：pytest + 黄金样本 ADIF 与 PDF 快照比对。

## 4. 数据源接入需求

### 4.1 通用要求

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| SR-COM-001 | 采用连接器插件架构，新增数据源无需修改核心代码，具备统一的接口定义（连接、拉取、解析、健康检查） | 必须 |
| SR-COM-002 | 所有网络请求须支持超时、重试（指数退避）、并发上限与失败隔离，单源失败不得阻断其他源 | 必须 |
| SR-COM-003 | 遵守各源速率限制；达到限额时排队等待并在 UI 显示预计等待时长 | 必须 |
| SR-COM-004 | 本地缓存查询结果（Callbook 建议 TTL ≥ 30 天），支持手动刷新与失效 | 必须 |
| SR-COM-005 | 增量同步：记录各源最后同步时间/游标，重复同步不产生重复记录（幂等） | 必须 |
| SR-COM-006 | 凭据与业务数据分离存储并加密；日志中敏感字段须脱敏 | 必须 |
| SR-COM-007 | 每个连接器提供「连接测试」与「最近错误」诊断信息 | 应当 |
| SR-COM-008 | 支持代理设置（HTTP/SOCKS5）与自定义 CA 证书 | 应当 |
| SR-COM-009 | 提供导入/同步任务的执行历史（时间、来源、条数、失败明细） | 必须 |
| SR-COM-010 | 任何自动上传行为默认关闭，须用户显式开启并二次确认 | 必须 |
| SR-COM-011 | **用户凭证仅保存于本机加密存储（首选操作系统密钥库），不得以明文写入配置文件、数据库、日志、导出包或任何云同步位置** | 必须 |

### 5.2 台站与档案模型

- **Station（本台配置）**：呼号、操作员、QTH、网格、CQ/ITU 区、DXCC、地址、印章/签名图片、默认卡片模板；
- **Counterparty（对方档案）**：呼号 → 姓名/QTH/地址/网格/实体，含来源、更新时间、是否锁定；
- **Template**：卡片模板（见第 7 章）；
- **CardBatch / CardItem**：制卡批次与单卡明细；
- **Job**：导入/同步/制卡任务及状态。

| 编号 | 规则 | 处理方式 |
| --- | --- | --- |
| VAL-001 | 日期时间统一为 UTC，检测本地时误录（如与相邻记录整体偏移） | 规范化 + 警告 |
| VAL-002 | 波段与频率一致性校验（频率是否落在波段范围内） | 警告 |

### 5.6 确认状态模型

每条 QSO 在以下维度上维护状态，并派生统一的「制卡需求」结论：

| 维度 | 取值 |
| --- | --- |
| 我方发卡（qsl_sent） | 未发 / 已发 / 已请求 / 无需 / 已忽略 |
| 我方收卡（qsl_rcvd） | 未收 / 已收 / 已请求 / 无效 / 已核验 |
| LoTW 确认 | 未上传 / 已上传 / 已确认 / 已作废 |
| eQSL 确认 | 未发 / 已发 / 已确认 / AG |
| 总体状态（派生） | 待制卡 / 已制卡待寄 / 已寄出待回 / 已确认（无需纸质）/ 退件 / 已完成 |

规则示例（可配置）：若 lotw_qsl_rcvd = Y 且用户偏好「已确认不发卡」，则该 QSO 的总体状态为「已确认（无需纸质）」，不进入制卡集合。

## 7. 卡片版式与模板设计需求（详规）

### 7.1 常用卡片尺寸

| 规格 | 毫米（mm） | 英寸（in） | 备注 |
| --- | --- | --- | --- |
| **90 × 140（默认规格）** | **90 × 140** | — | **本项目默认卡片尺寸**；四边各加 3 mm 出血，版面文件尺寸 96 × 146 mm |
| 经典 QSL 卡 | 88.9 × 139.7 | 3.5 × 5.5 | 最通行；两台并排拼版 |
| 美式明信片 | 101.6 × 152.4 | 4 × 6 | 便于冲印 |
| 大卡 | 127 × 177.8 | 5 × 7 | 收藏/纪念 |
| ISO A6 | 105 × 148 | ≈4.13 × 5.83 | 公制标准 |
| 国内常用公制 | 90 × 140 | — | 与默认规格一致，兼容国内多数印刷厂 |
| 自定义 | 用户输入 | — | 须校验拼版可行性 |

> 默认规格：**卡片成品 90 × 140 mm，四边各加 3 mm 出血**，版面文件尺寸即 96 × 146 mm；成品线向内侧 3 mm 为安全区，文字与关键元素应位于此线内。
>
> 精度要求：内部一律以毫米或 1/1000 英寸为单位保存，避免浮点舍入造成累计偏移；经典 3.5×5.5 in 精确等于 88.9×139.7 mm，Letter 纸纵向两行恰好 279.4 mm（= 2 × 139.7），故美式 4-up 通常为零上下边距拼版——系统在拼版计算中须能表达「零边距」并给出警告。

## 8. 打印与拼版需求

> **场景定位（v1.1 确认）**：**家用打印机（A4/Letter 喷墨或激光）为主要使用场景**，默认输出通用 PDF、开箱即用；商业印刷为**可选增强**，通过可视化选项切换为 PDF/X-1a、CMYK、300/600 DPI 等，不要求普通用户理解印刷术语（见 7.9 CAL-007/008）。

### 8.1 拼版计算（示例，含 3 mm 出血与 2 mm 间距）

| 纸张 | 卡片尺寸 | 每页张数（参考） | 说明 |
| --- | --- | --- | --- |
| A4 210 × 297 | 88.9 × 139.7 | 4（2 × 2） | 两列两行，纵向余量充足 |
| Letter 215.9 × 279.4 | 88.9 × 139.7 | 4（2 × 2） | 纵向 2 × 139.7 = 279.4，须零上下边距 |
| A3 297 × 420 | 88.9 × 139.7 | 6（3 × 2） | 预留裁切余量，稳妥 |
| A4 210 × 297 | 105 × 148（A6） | 2（2 × 1） | 或旋转 1 × 2 |
| A4 210 × 297 | **90 × 140（默认）** | 4（2 × 2） | 默认规格；含 3 mm 出血后单卡 96 × 146 mm，A4 仍可 2 × 2 拼版 |

系统须根据纸张、卡片、出血、间距、边距自动求解最优行列数，并在不可行时给出明确原因。所有拼版参数可覆盖。

### 8.2 印刷质量要求

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| PRN-Q-001 | 输出分辨率 ≥ 300 DPI（位图素材按最终尺寸核算），矢量元素无损 | 必须 |

qslcard sync --source qrz-logbook --source lotw --source clublog

# 按规则选卡并生成拼版 PDF
qslcard cards build --rule "needs-card" --template classic-01 \
    --paper A4 --cards-per-page auto --duplex --bleed 3 --dpi 300 \
    --out ./out/batch-20260911.pdf

# 补全地址
qslcard callbook fill --rule "direct-only" --provider qrz,hamqth

# 生成投递标签
qslcard labels build --route direct --format avery-5160 --out ./out/labels.pdf

# 更新状态并导出 ADIF
qslcard track mark --batch batch-20260911 --status sent --date 2026-09-12
qslcard export adif --out ./out/updated.adi
~~~

## 18. 隐私保护与凭证本地化控制

> **核心原则：用户提供的凭证仅限本地保存、仅限本地调用。** 凭证不出本机、不上云、不进入任何导出物，且只用于向该凭证对应的服务官方端点发起请求。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| PRIV-001 | 凭证本地化存储：所有凭证只能保存在本机加密存储中，首选操作系统密钥库（Windows DPAPI / Credential Manager、macOS Keychain、Linux Secret Service）；无密钥库环境须使用用户主口令加密的本地保险库，**禁止明文降级存储** | 必须 |
| PRIV-002 | 仅限本地调用：凭证在内存中仅用于向该凭证对应服务的官方 HTTPS 端点发起请求；禁止写入任何远程服务、禁止跨服务复用、禁止以任何形式回传 | 必须 |
| PRIV-003 | 不出本机：不实现云同步、远程账号体系、远程日志与使用统计；不向开发者或第三方发送凭证、QSO 记录、地址或行为数据 | 必须 |
| PRIV-004 | 出站白名单：网络模块维护目标端点白名单（各数据源官方域名），非白名单目标默认拒绝并在界面提示 | 必须 |
| PRIV-005 | 离线模式：一键关闭全部出站网络；关闭后 ADIF 导入、缓存地址、制卡与导出仍可正常使用 | 必须 |
| PRIV-006 | 传输安全：仅允许 TLS 1.2 及以上；证书校验失败即中止，不得静默忽略；如允许例外配置须显著警告并记录审计 | 必须 |
| PRIV-007 | 最小查询：仅向服务请求完成当前功能所必需的数据，请求中不夹带其他用户的记录或无关字段 | 必须 |
| PRIV-008 | 界面防泄露：凭证默认掩码显示；复制需二次确认；剪贴板内容可配置定时清空（默认 60 秒） | 应当 |
| PRIV-009 | 清除与生命周期：提供单条/全部凭证清除；程序退出时清除内存中的口令与 API Key；卸载时清除密钥库条目；提供「隐私自检」报告，列出本机存有哪些敏感数据及其位置 | 必须 |
| PRIV-010 | 导出与备份净化：配置导出、数据备份、诊断包与模板包生成时自动剔除凭证；确需迁移凭证时，只能通过**主口令加密的专用凭据包** | 必须 |
| PRIV-011 | 地址与个人信息：对方地址仅本地存储、不参与任何联网回传；导出与报表可选脱敏；提供一键清除个人数据（见 DAT-005） | 必须 |
| PRIV-012 | 使用审计：仅记录凭证「被使用」的事件（时间、用途、目标端点），不记录凭证内容，用户可查看与清除该审计 | 应当 |

### 18.1 凭证生命周期

~~~text
录入（用户显式输入）
  → 加密写入本机密钥库/本地保险库（界面此后仅掩码显示）
  → 使用时于内存解密，仅用于向对应服务官方端点请求
  → 使用结束立即从内存清除
  → 用户可随时单条/全部清除；程序退出清除；卸载清除密钥库条目
  任何阶段：不落明文、不入日志、不进备份/诊断包/导出物、不上传
~~~

| 配置文件与日志 | 无凭证明文（自动扫描并报告） |
| 出站连接 | 仅白名单官方端点；离线模式为 0 连接 |
